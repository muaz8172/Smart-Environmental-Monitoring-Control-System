# IR 7.0 AI Brain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the one-way sensor monitor into a closed-loop "IR 7.0" system. A Python AI brain predicts, decides, explains and logs fan actions; a human can override it; and the Arduino falls back to its own rules if the AI disappears. Everything is shown on an offline HTML page served by Node-RED.

**Architecture:** The Arduino gets serial commands and a 10 s watchdog. The bridge (`Module_4`) becomes two-way: serial ⇄ MQTT. The new `Module_7_AI_Brain.py` is pure decision functions plus a thin MQTT loop. Node-RED serves `/ir7` (HTML) and `/ws/ir7` (websocket), and exposes `/ir7/events` from SQLite.

**Tech Stack:** Arduino C++ (Uno, Proteus), Python 3.14 + paho-mqtt 2.x + pyserial + sqlite3 + pytest, Mosquitto 1883, Node-RED (core http/websocket/mqtt nodes + node-red-node-sqlite).

**Spec:** `docs/superpowers/specs/2026-11-20-ir7-ai-brain-design.md`

## Global Constraints
- Every new or rewritten file starts with the header comment: `Muhammad Muaz Bin Md Fazli, UniKL MFI, topic: Smart Environmental & Monitoring System`. Code is short, with few comments.
- Fully offline: no CDN, no cloud, no API keys.
- Topics: data `muaz/iot/mfi`, AI `muaz/iot/mfi/ai`, commands `muaz/iot/mfi/cmd`, override `muaz/iot/mfi/override`.
- Serial commands are exactly `FAN:ON`, `FAN:OFF`, `AUTO`, each terminated by `\n`, at 9600 baud.
- Arduino watchdog is 10 s. Readings arrive every 2 s. Forecast window is the last 30 readings. Forecast horizon is 10 min. Pre-emptive trigger is ≤3 min. OFF hysteresis is 2 readings.
- AI fan triggers: temperature ≥37, humidity ≥60, dust ≥55 only, and only when occupied (distance <100). Comfort bands for score and alerts: T<37, 30<H<60, dust<55, 980<P<1050, light>500.
- `FAN_POWER_W = 5`. `GRID_KG_PER_KWH`: a cited Malaysia grid factor, with the source in a comment.
- Leave untouched: `Arduino/Module_3_V3/`, the V1/V2 Node-RED tabs, and existing `Sensor_data` rows.
- DB: `Database/Sensor_database.db`, new table `AI_Events`.

## Review Focus
1. Override `ON` while the room is unoccupied → the human wins and the fan stays ON (Task 2 test `test_override_beats_unoccupied`).
2. The brain receives a 7-field-firmware payload with no `"mode"` key → it still decides normally (Task 2 test `test_missing_mode_key`).
3. Fewer than 5 history points, or a flat series → forecast returns `None`, with no division by zero (Task 1 tests `test_forecast_short_history`, `test_forecast_flat`).
4. An override payload in lowercase or garbage (`"on"`, `"xyz"`) → `"on"` is accepted as `ON`, and garbage is ignored with the mode unchanged (Task 2 test `test_override_normalise`).
5. A command arrives while the serial port is closed or reconnecting → it is dropped with a log line and the bridge doesn't crash (Task 3 test `test_write_cmd_no_port`).

### Task 1: AI pure functions (score, forecast, anomalies, old rule)

**Files:**
- Create: `Python/Module_7_AI_Brain.py` (functions only in this task)
- Test: `Python/test_ai_brain.py`

**Interfaces:**
- Produces:
  - `health_score(r: dict) -> int`: 0–100. 100 when every value is inside its band. Each band violation costs a share scaled by how far out it is, clamped to ≥0.
  - `forecast(history: list[dict], key: str, limit: float) -> float | None`: minutes until `key` reaches `limit`. Least-squares slope over the last 30 points, 2 s spacing. Returns `None` if there are fewer than 5 points, the slope is ≤0, the value is already ≥ the limit, or the ETA is over 10 min.
  - `anomalies(prev: dict | None, r: dict) -> list[str]`: "sudden spike" text when a one-step jump is above `SPIKE = {"temperature": 5, "humidity": 15, "dust": 30}`. "sensor fault" text when a value is out of `RANGE = {"temperature": (-10, 80), "humidity": (0, 100), "pressure": (300, 1100), "dust": (0, 1000), "light": (0, 1023), "distance": (0, 500)}`. `STUCK_CHECK = False` (constant only).
  - `old_rule(r: dict) -> bool`: the V3 firmware rule: occupied and (T≥37 or H≥60 or dust≥55 or P≥1050 or light≤500).
  - `NORMAL = {"temperature": 30, "humidity": 50, "pressure": 1010, "dust": 30, "light": 700, "distance": 50}`: test fixture reused later.

### Task 2: Brain decision engine (decision, hysteresis, override, explanation, energy, events)

**Files:**
- Modify: `Python/Module_7_AI_Brain.py`
- Test: `Python/test_ai_brain.py`

**Interfaces:**
- Consumes: Task 1 functions.
- Produces: `class Brain`:
  - `Brain()`: history (last 30), override `"AUTO"`, fan `False`, off-counter, energy Wh (`ai_wh`, `old_wh`), `last_anoms`.
  - `step(r: dict, dt_s: float = 2) -> dict`: returns `{"score": int, "forecast": {key: eta_min}, "anomalies": [str], "alerts": [str], "would": "ON"|"OFF", "fan": "ON"|"OFF", "mode": "AI"|"HUMAN", "reason": str, "energy": {"ai_wh": float, "old_wh": float, "saved_wh": float, "co2_g": float}, "events": [(type, msg)]}`.
  - `set_override(p: str) -> None`: normalises with `.strip().upper()`; accepts AUTO/ON/OFF and ignores anything else. If the value changed, queues an event `("OVERRIDE", ...)`.
  - `command(self) -> str`: `"FAN:ON"` / `"FAN:OFF"` from the last `fan`.
- Decision: `would` = ON if occupied and (any trigger ≥ limit or any forecast ETA ≤3). Leaving ON needs 2 consecutive "clear" readings (hysteresis). Unoccupied → OFF immediately. `fan` = the override value if the override is not AUTO, otherwise `would`.
- `alerts`: band violations that are not fan triggers (low light, pressure out of band, humidity ≤30), as text.
- `reason`: one sentence. Examples of the exact shapes: `"Fan ON: humidity 58.0 % rising, will exceed 60 % in ~1.2 min, cooling early."`, `"Fan ON: temperature 38.0 °C over 37 °C."`, `"Fan OFF: room unoccupied."`, `"Fan OFF: all fan-fixable readings normal."`, and with an override `"HUMAN OVERRIDE (fan ON). AI would turn it OFF: …"`.
- Energy: `ai_wh += FAN_POWER_W*dt_s/3600` when the fan is ON; `old_wh` likewise when `old_rule(r)` is true; `co2_g = saved_wh/1000*GRID_KG_PER_KWH*1000`.
- Events: on a `fan` flip `("DECISION", reason)`, on anomaly start/end `("ANOMALY", text)`, plus queued override events. Cleared each step.

### Task 3: Two-way bridge + brain MQTT loop + AI_Events log

**Files:**
- Modify: `Python/Module_4_MQTT_Mosquitto.py`
- Modify: `Python/Module_7_AI_Brain.py` (add `log_events`, `main`)
- Test: `Python/test_bridge.py`, `Python/test_ai_brain.py`

**Interfaces:**
- Consumes: `Brain` (Task 2); the existing bridge `parse`, `serial_frames`, `simulated_frames`.
- Produces:
  - bridge `parse(frame: str) -> dict | None`: accepts 7 or 8 fields. The 8th must be `AI`/`LOCAL`. Adds `"mode"` (default `"LOCAL"`).
  - bridge `write_cmd(cmd: str) -> bool`: writes `cmd.strip()+"\n"` to the module-level `SER` under `LOCK` if it is open. Otherwise it logs and returns `False`. In simulate mode it updates `SIM = {"cmd": str|None, "t": float}` instead.
  - bridge subscribes to `muaz/iot/mfi/cmd` (topic = `--topic` + `/cmd`) in `on_connect`. `on_message` → `write_cmd`.
  - `simulated_frames()`: if `SIM["cmd"]` was set within the last 10 s, fan = that command and mode = `AI`, otherwise the old rule and `LOCAL`. Emits 8 fields.
  - brain `log_events(db_path: str, events: list[tuple[str, str]]) -> None`: `CREATE TABLE IF NOT EXISTS AI_Events (ID INTEGER PRIMARY KEY AUTOINCREMENT, Timestamp TEXT DEFAULT (datetime('now','localtime')), Type TEXT, Message TEXT)`, then inserts the events. `sqlite3.Error` → log, no raise.
  - brain `main()`: args `--broker` (localhost), `--topic` (muaz/iot/mfi). Subscribes to `topic` and `topic/override`. On data: `out = brain.step(json)`, then publish `json.dumps(out minus "events")` to `topic/ai`, publish `brain.command()` to `topic/cmd`, then `log_events(DB, out["events"])`. `DB` = `Database/Sensor_database.db` resolved relative to the file (`Path(__file__).parent.parent / "Database" / "Sensor_database.db"`).
